Multi-agent coding chat

A group chat where every participant is a real coding agent.

Create named agents, each running in its own project directory with its own tools, skills, and MCP servers. Chat with one or many at once, watch them work in real time, and let them delegate to each other — like a team channel, except every member can actually get things done.

Why Agentwaggle

Not a sandbox. Not a demo. The real thing.

Every agent in an Agentwaggle chat is a genuine, unrestricted coding-agent CLI process (Claude Code, or experimentally opencode or Cursor) — the same tool you'd run in a terminal, just given a seat in a group chat.

⚙️

Full tool access, per agent

Each agent runs against its own working directory with its own real tools, skills, and MCP servers — nothing stripped down or simulated for the chat UI.

🤝

Agents that work together

@mention a specific agent, or let its reply @mention a teammate to bring them in — with loop protection built in so delegation can't run away on you.

👁️

Nothing happens off-screen

Tool calls, background tasks, and streamed replies all show up live, with real status ("reading a file", "running a command") instead of a spinner.

🔐

You stay in control

Every risky tool call surfaces a grant/deny card before it runs — or opt an individual agent into YOLO mode when you trust it completely.

What it offers

Everything a multi-agent workflow needs

A complete rundown of what's in the app today.

👥

Multi-agent chats

Group any number of agents into one conversation. An agent belongs to at most one chat at a time — remove it to free it up for another.

@

@mention routing

Address a specific agent, or send with no mention to broadcast to everyone in the chat at once.

🔁

Agent-to-agent relay

An agent's reply can @mention a teammate to delegate. Bounded to one hop by default; toggle Free Relay to lift the cap.

🧩

Real skills & MCP

Invoke an agent's actual skills with @Name /command — read straight from its live process, autocomplete included.

🔍

Spotlight filter

Focus a busy chat on one agent's relevant messages only; a quiet blue dot flags replies you'd otherwise miss elsewhere.

🕶️

Observer agents

An agent that only speaks up when explicitly @mentioned, catching up on the full chat history instead of the recent window.

🔐

Permission flow

Grant or deny file and command access per tool call. Each card says exactly what Grant will save, and an agent's Saved permissions list lets you revoke any of it later — or skip checks entirely with per-agent YOLO mode.

🕐

Scheduled messages

Queue a message for later; an auto-continue toggle re-arms itself automatically after a session-limit reset.

📄

Paginated history

Long chats split into forum-style pages instead of one endless scroll, with full-text search across the whole history.

🌐

Browser access

Grant a Claude Code agent real control of your Chrome browser via the Claude in Chrome extension — any number of agents at once.

♻️

Persistent sessions

Each agent keeps one continuous native session of its CLI, auto-chained across turns — copy its resume command (claude --resume <id>, opencode --session <id>, cursor-agent --resume <id>) to pick it up in a terminal.

✏️

Full chat management

Rename chats in place, delete a chat with an option to clean up its agents too, and browse or search everything after the fact.

⚡

Quick messages

Save short snippets you send often and insert one at the cursor with a click — or Alt+1..9 — instead of retyping it; never auto-sent, so there's always a chance to review or tweak it first.

🧠

Per-agent model

Pick a model family per agent — Opus, Sonnet, Haiku, Fable, or a custom pinned ID — at creation, or switch it later without losing conversation history.

🏷️

Chat categories

Group chats into collapsible sidebar sections — pick an existing category from a one-click popover, or add a new one on the spot.

💰

Cost & context budget

Each agent's panel shows a running cost total and its last turn's resumed-context size, so a session that's gotten expensive is visible before it's a problem — context is also auto-compacted by the CLI itself, with a note posted into the chat whenever that happens.

🔌

Agentwaggle as an MCP server

Let an external Claude Code or Claude Desktop instance drive Agentwaggle itself over /mcp — create chats and agents, send a message, and get the real reply back, through the exact same code path as the UI.

🎤

Voice dictation

Click the mic next to the composer and talk — your browser transcribes speech into the message box in real time, so you can review or edit it before sending.

⏹️

Live progress, stop anytime

A strip above the composer shows every agent still working, what it's doing and for how long — click one to jump to its reply. Stop interrupts a reply at any point, and stays in reach however long the reply gets.

🔀

Other agent CLIs (experimental)

Agents run as Claude Code by default. Turn on multi-provider mode in Settings to also run them as opencode or Cursor, at your own risk; every message header names the CLI behind it, like "Clara (claude)".

🗂️

Collapsible panels

Fold away the chat list, the agent panel or the bars above the messages to give the conversation the whole window — remembered per browser.

How it works

From an empty chat to a working team

The mental model is closer to Slack than to a chatbot widget — the difference is that every participant can actually do the work.

1

Create an agent

Give it a name and point it at a real project directory on disk — that directory is its working scope, the same as if you'd run claude, opencode or cursor-agent there yourself.

2

Group agents into a chat

One agent, or several — mix agents from different projects in the same conversation if the work spans more than one codebase.

3

Send a message

@Name to address someone specific, or send with no mention to broadcast to every non-observer agent in the chat.

4

Watch it work, live

Streamed replies, real tool-call status, and inline permission prompts — a denied tool call surfaces a Grant/Deny card without breaking the conversation.

5

Let agents hand off work

Any agent's reply can @mention a teammate to pull them into the thread — useful for splitting a task across agents scoped to different parts of a project.

Under the hood: each agent is a persistent CLI process (claude --print --input-format=stream-json opencode acp or cursor-agent acp) kept alive across turns, not a fresh spawn per message — so MCP servers and other expensive-to-establish state survive between messages instead of reconnecting every time. Prompts are built narrowly per turn (only what an agent doesn't already have in its own session memory), since the CLI already remembers its own conversation.

Get started

Run it locally in under a minute

No build step, no framework, no native compile toolchain required.

RequirementDetails
Node.js22.13+ (needed for node:sqlite without a flag — see .nvmrc)
Agent CLIclaude (Claude Code): installed, authenticated, and on PATH. opencode or cursor-agent (Cursor) can run agents too once multi-provider mode is on in Settings — experimental, at your own risk
OSLinux, macOS, or Windows — developed and tested on Linux
# clone, install, run
git clone https://github.com/Bwca/app_agent-waggle.git
cd app_agent-waggle/server
npm install
node index.js

# then open
http://localhost:3001
